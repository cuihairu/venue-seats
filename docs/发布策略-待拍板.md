# 包发布策略 — 待拍板

todo.md「待拍板」唯一开放项的前置事实与选项（2026-10-15 整理）。
**本文档只备料，不做任何发布动作**；正式发版红线不变：版本号只能由用户给出并手动触发。

## 前置元数据现状（2538060 已备）

- npm 侧 7 个包均挂 `@venue-seats/*` scope，version `0.0.1`；`license: MIT`、
  `files: ["dist"]`、`publishConfig`（发布时 main/types/exports 切到 `dist/`）齐备。
- 还缺：`repository` 字段（npm publish 会警告）、`publishConfig.access: "public"`
  （npmjs 上 scope 包默认 restricted，不加必失败）、CI 侧 `NPM_TOKEN` secret。
- Flutter 侧 `venue_seats 0.0.1`，`publish_to: none`；`description` 已写，
  还缺 `repository` / `homepage`（`dart pub publish --dry-run` 会报）。

## 决定 1 — npm 范围与 registry

| 选项 | 内容 | 代价 |
|---|---|---|
| A（建议） | 维持 `@venue-seats/*`，发 npmjs 公共源，每包加 `publishConfig.access: "public"` | 首发需 `--access public`（或配置）；scope 可占住命名 |
| B | 去 scope 改 `venue-seats-*` 平铺名 | 需改 7 个 manifest + 全部 import，收益仅是省 access 配置 |
| C | scope 发 GitHub Packages（npm.pkg.github.com） | 消费方要配 .npmrc 鉴权，采用门槛高 |

`@venue-seats/demo`（apps/demo）建议永远 `private: true` 不发布；
`@venue-seats/venues-demo` 是示例数据包，随 A 一并发布即可（亦可决定 2 独立拍）。

## 决定 2 — Flutter 分发通路

| 选项 | 内容 | 代价 |
|---|---|---|
| A（建议） | pub.dev：删 `publish_to: none`，补 `repository`/`homepage`，版本随 npm 同步 | 要过 `dart pub publish --dry-run` 的 package 评分（文档、example 可选） |
| B | git 依赖：保持 `publish_to: none`，消费方 `flutter pub add` 走 git ref | 零注册面，但消费方配置繁琐、无版本解析 |
| C | 仓库内 vendored/子树拷贝 | 最省事，长期漂移风险最高 |

B 可作为 A 之前的过渡态（现状即 B，只是未写明）。

## 决定 3 — 发版通路（受红线约束）

| 选项 | 内容 | 红线符合性 |
|---|---|---|
| A（建议） | 用户手动触发：`workflow_dispatch` 带 `version` 输入 + GitHub Environment 保护（需用户批准），跑全量门禁后 `npm publish` / `flutter pub publish` | 符合——版本号与触发都在用户手里 |
| B | nightly 滚动：`schedule` 检测 48h 内有提交则发 `nightly` dist-tag / 滚动分支二进制 | 符合——nightly 属允许面，且不进 Releases 页正式版 |
| C | A+B 并行 | nightly 面向尝鲜，正式版仅用户触发 |

无论选哪档：**未通过验收测试的产物不得出现在 Releases 页、不得称正式版**
（2026-10-11 红线）。验收门禁 = `pnpm -r build && pnpm -r test:coverage` +
`flutter analyze && flutter test` 全绿 + 用户人工验收。
